# Owner-scoped memory and bounded recall (#9 / #10)

## Integrated processing

A memory run processes its exact, durable delivery window. It can retain legacy `notes`, or submit up to four total structured `changes`: add, merge, correct or conflict. Each structured interpretation has its owning Agent, subject, canonical key/value, topic, paraphrase aliases, epistemic label and optional half-open validity interval. The single human operator is subject `null`; Agent subjects use the actual session-instance UUID. These records are not shared truth. `verified:false` and `independentSupport:null` are deliberate, including for self-reports.

Sources must be non-deleted originals actually supplied in the memory delivery window with the same current revision. A self-report requires the original author to match the subject. Explicit targets and parents must be that Agent's current memories actually supplied in this request. Nonexistent, unobserved, foreign-session and wrong-subject evidence rejects the result transaction, without acknowledging the input cursor. Private state, memory, cursor receipts and candidate invalidation commit together.

A new direct self-report can correct an observed interpretation with new original evidence. Older interpretations remain as SUPERSEDED audit history. Canonical equivalents in the same subject/key/value/epistemic/time interval are reconciled into one current record while retaining original source references. Explicit merge cannot relabel an inference as a self-report or merge separate time periods. Non-overlapping target periods cannot be overwritten as a correction. Unresolved alternatives are CONFLICT, and interpretations derived from a conflicting parent retain CONFLICT. Repetition never increases an independent-support count.

Canonical-key equivalence and aliases are model-authored, not an independently proven semantic equivalence algorithm. Unrelated keys or missing aliases may evade reconciliation or retrieval. Legacy text-only notes preserve their known source versions where available, and otherwise carry unknown evidence/meaning rather than fabricated certainty. Neither a type check nor the fixture tests certify that a live model chooses appropriate meanings.

## Dependency invalidation and retained history

V6 adds `memory_metadata`, `memory_edges` and `memory_changes` without replacing base memory or public message rows. Editing/deleting an original invalidates direct and transitive memory dependants. Working-state entries can declare `derivedFrom` memory IDs; reconciliation or source invalidation removes those dependent current entries and preserves their private journal. Candidate/run checks reject stale interpretations. Automatic recall, private paging and explicit LOOKUP all exclude INVALID/SUPERSEDED memories and missing, deleted or wrong-version evidence. CONFLICT remains visible as an unresolved alternative, never an established fact.

Corrections, lineage, invalidation and original versions survive restart and verified full-database backup/restore. The source message's earlier text is not reconstructed after an edit; a retained memory is not a verbatim source archive. Raw private DBs and journals can retain superseded/deleted information for audit. Public history/export and current retrieval do not expose that memory history. This is not secure deletion from old runs, backup media or browser copies; the separate retention/security work remains open.

## Selection, lookup and budgets

MemoryRetriever is replaceable. The implemented meaning-aware retriever adds declared aliases, subject links and validity-time selection to the lexical/evidence baseline, without external calls or a mandatory embedding service. Current messages, named/addressed participants, unresolved questions and private-state entries seed automatic retrieval before participation. Memory runs also recall relevant prior interpretations so correction/merge does not depend on knowing unseen memory IDs. Selection includes the originals with their actual IDs/revisions. Missing results, unknown provenance, omitted items and bounded source excerpts remain explicit. Lack of a result is not proof that the information never existed; exact quotations require originals.

An explicit ISO date is treated as a UTC date boundary; the current implementation recognizes literal yesterday/tomorrow in Japanese relative to the supplied clock and explicit historical-query words. This is limited query parsing, not general temporal or coreference understanding. The SQL and fixture comparisons test declared metadata, not learned semantic similarity.

Selection budgets the actual serialized model request, including persona, private state, mandatory chronological input, review differences, recalled originals, sources, schema/structured-output framing, a worst-case bounded repair and output reservation. UTF-8 byte count plus framing allowance is recorded as `utf8-upper-bound` with `tokenizer:unknown`: deliberately conservative engineering estimation, not a universal guarantee for arbitrary provider tokenization or hidden provider-added prompts. The HTTP adapter checks the same request builder again. Bound contexts are not silently trimmed after their observation manifest is created.

For non-memory requests, selection normally leaves up to 4,096 context characters and 8,192 estimated tokens for explicit LOOKUP, within the already authorized limits. Existing mandatory state/review evidence and an indivisible first observation take priority when needed. Therefore headroom is not a promise that arbitrary lookups will fit. An overlarge lookup rejects atomically, preserving the old request and its cursor; at most two lookup rounds and the existing finite call-attempt limits remain. An unfit mandatory context stops that Agent with CONTEXT_LIMIT rather than looping indefinitely or claiming unseen input was observed.
