# 任意会話の読解評価手順

状態：評価準備。実モデルの実行・人間の採点を済ませた記録ではありません。20導入題材は`config/evaluation/scenarios.json`を使用します。runtimeの順序・発言数・担当役を固定して合格させません。

## 試行を開始する前に固定すること

モデルID/API/能力設定、人格の版、入力/出力予算、承認commit、各runの時間/回数上限、総実行予算、採点者、反復回数をmanifestと評価票へ記録します。標準の計画は各題材3回ですが、費用・時間に合わせて実行前に変更し、その変更と母数を残します。CLIは1実験ずつの上限を守るもので、複数実験の費用を自動承認・一括実行しません。

比較は同じモデル・人格・入力予算で、旧方式、新状態＋想起、必要な原文を明示供給した対照を分けます。旧方式の異なるcommitには記憶以外の変更もあり得るため差分を記録し、差の全てを記憶の効果と断定しません。対照で供給した原文が本当にモデル要求に含まれることを私有診断で確認します。通常の初期題材だけの会話と、履歴/編集/資料/故障を操作する制御ケースの結果を混ぜません。

## 各runの採点

次の観点を0（失敗）、1（部分的）、2（要求を満たす）、NA（その機会がなく判定不能）で記録します。NAは成功に換算しません。短い引用または原文ID・runID・記憶/状態versionで根拠を指定し、印象やモデルjudgeの点数だけで合格としません。

| 観点 | 2点の根拠 | 失敗例 |
|---|---|---|
| 独立性・相互作用 | 別入力/私有状態の三者を識別し、Cの発言が後のA/Bの判断・発言に影響する具体箇所がある | 単一台本、他者の代弁、内容を受けない順番応答 |
| 人格・主体 | 語尾だけでなく関心・判断・態度の違いがある。本人の経験、他者の申告、推測を区別する | 経験の誤帰属、同じ話者の別名化 |
| 継続状態・再参加 | 沈黙中の疑問・予定が本人の次の入力へ戻り、適切な時に参加か沈黙継続を選ぶ | 疑問の無理由消失、予定だけで強制発言 |
| 記憶・根拠 | 古い根拠・言い換え・時点・訂正を扱い、不明は不明とする | 捏造した約束、訂正前の値、要約を逐語引用扱い |
| 会話の流れ | 未回答/部分回答、複数話題、同意・冗談・共感を扱い、自然に休止できる | 毎回の締め質問、堂々巡り、強制総括、全員への応答強制 |
| 競合・障害 | 遅いモデルも有効な機会を持ち、未確認の候補を出さない。障害と沈黙を区別できる | API不応答を自然な沈黙として成功に計上、同数発言の強制 |

ケースの対象観点に0があるrunはそのケースの不合格、対象観点に1/NAがあれば未達/判定不能として残します。制御不変条件の違反、所有権違反、原文の捏造は他の点数で相殺しません。全体合格率などの品質閾値は実行前に承認した値を使い、結果を見てから閾値を下げません。未承認の閾値では全体の完成を宣言しません。

## 失敗の切り分けと提出

関連根拠が検索候補へ入らないのか、予算で選ばれないのか、入力に供給されても生成側が誤ったのかを分けます。モデル入力と出典versionを確認し、取得率・誤取得・追加呼出し・応答時間と、人による解釈/自然さの評価を別欄にします。

終了が全員沈黙、Provider障害、設定不良、予算到達、人間停止のどれかを記録します。失敗・無発言・中断を母数から除外しません。seedだけで外部モデルの再現を保証しません。対照条件、試行母数、代表的成功/失敗、再試行数、費用上限と実際のusage不明率を提出します。

評価票は少なくとも `{scenario,condition,trial,commit,configHash,privateRecordingLocation,stopReason,scores,evidence,reviewer,reviewedAt,verdict}` を持ちます。原データの私有情報・認証・プロンプトを公開Issue/CIへ転載せず、公開する要約は別に作成します。人間が読んでいない記録にreviewerやhumanReviewedを作りません。
