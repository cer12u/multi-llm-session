# Owner purpose feedback and voluntary quiet (#13)

The real decide/draft/review context now contains `conversation`: this owner's last three published purposes, a bounded public-message index and advisory repetition signals. The current candidate already supplies the present purpose. Responses and unresolved questions remain in the ordinary input/private-state paths. Purpose records are the owner's declared intention, not proof that other participants were satisfied. Their excerpts are explicit; unpublished and other owners' purposes are never selected. Deleted or differently versioned originals are excluded. These indexes are not observation evidence: an absent original must be fetched before citing it in a state update. All metadata is included before input budgeting and manifest binding, not appended to a full request after selection.

`repetitionSignals` examines at most eight current originals. It reports repeated explicit questions with the same author/text/recipient/reply target, three highly overlapping contributions by multiple authors, and structural self-replies. Normalization and character-trigram overlap are lexical heuristics, not semantic equivalence or judgments of usefulness. There is no automatic publication veto. A self-reply may be a necessary correction; agreement, empathy, jokes, experiences and continued discussion do not need new facts to qualify for participation. The model policy still forbids a central moderator, scripts for other people, compulsory closing questions, equal turn counts and forced summaries.

The owner can use its existing atomic private-state patch to retain one `kind:intention` entry with `participation:{code:'SATISFIED'|'CONTENT_LOOP',throughInput}`. This is allowed only in decide/draft/review after a complete chronological delivery window. The input boundary must equal the recorded delivered boundary. A CONTENT_LOOP assessment requires two distinct original message references that passed the normal actually-supplied/version/session/ownership checks. A merely listed hint, fabricated ID, stale version or wrong owner's state cannot establish that evidence. The patch, chosen action, cursor and journal commit together. No new state-patch administration privilege exists.

ABSTAIN, DEFER and DROP remain the actual means of withholding a contribution; storing an assessment alone is not a new command. Existing finite waits, autonomous opportunities, budgets, errors and generation fencing remain in force. The operator status panel and CLI show a distinct CONTENT_LOOP reason only for an otherwise quiet/deferred owner with an assessment covering the current input high-water mark. Provider failures, offline Workers, active inference, budget stops and operator pause take precedence. New source or message input makes an earlier assessment historical; it does not delete past private understanding or reset Provider failures. The owner can reconsider and replace/remove the assessment. No heuristic or stored assessment blocks a new proposal automatically.

Storage reuses V6 private-state/journal/candidate records. Online backup/restore and current original invalidation preserve the normal audit/current-knowledge distinction. Older binaries with strict schemas may not accept the optional field; operational rollback uses the corresponding verified pre-update backup and binary. Public deletion is not forensic erasure of old private journals/backups.
