# チャット中心のセッションUI

## 位置づけ

この改修は専用WebアプリをSlackに近いチャット操作へ変更するものです。Slackサービスへの接続・Bot追加ではありません。実LLMで3者以上の任意会話が成立することの実証ではありません。

## 操作

- 左の `# セッション` 一覧から切り替えます。追加ボタンでキャラクターとモデルを選びます。作成だけでは推論を開始しません。
- 中央の履歴は発言者・時刻・日付・会話再開の区切りを表示します。連続する同じ話者の発言をまとめ、入力欄は画面下に固定します。時刻はJSTです。
- Enterで送信、Shift+Enterで改行します。IME変換中のEnterは送信しません。送信先セッションと再送キーは送信操作開始時に固定します。
- セッション別・返信元別の下書きは現在のタブのメモリに保存します。別セッションへの切り替えでは残り、リロード・ログアウトで消えます。本文をlocalStorage等には保存しません。
- 過去の発言を読んでいるとき、新着で末尾へ強制移動しません。新着ボタンで末尾へ移動します。セッション切り替え時も同じタブ内でスクロール位置を保持します。
- 発言の返信ボタンから右のスレッド表示を開きます。これは既存のreplyToに基づく表示上のまとめであり、別セッションや別のAgentコンテキストではありません。返信は中央の履歴にも表示され、同じセッションの全Agentが受信します。
- スレッドと中央履歴は現在取得済みの直近200件が対象です。古い返信を含む完全なスレッド履歴・無限スクロールは未実装です。検索は同じセッションの保存済み原文を最大50件表示します。
- 参加者一覧、検索、資料、実行設定、診断は右パネルに分離しました。管理者の未投稿候補や診断を通常の会話本文に混ぜません。
- 狭い画面では左一覧がドロワー、右パネルが全面表示になります。入力は画面内に残します。

## 検証の区別

UIテストは、実アプリのHTTP API・SQLite・Workerに接続して操作しますが、モデルは模擬です。IMEキーイベントの試験は合成イベントであり、全OS・日本語入力方式の組み合わせを実機検証したものではありません。

通常CIでは、既存の制御試験に加えてチャットの表示ヘルパーとブラウザー操作を確認します。結果・スクリーンショットは対象コミットのActions成果物を確認してください。実APIの品質・JSON遵守・自然な三者相互作用・会話継続と沈黙は未検証です。

## 意図的に含めていないもの

外部Slack連携、ユーザー間DM、絵文字リアクション、添付ファイル、音声、既存キャラクターの画像表示、複数人のユーザーACL、永続的な未読状態は含めていません。見た目だけで動かないボタンは配置しません。初期版は引き続き単一運用者の非公開ラボ用です。
